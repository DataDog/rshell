Auto-improve skills

skilltrain now owns the train loop

The old shell-only make trainloop behavior is implemented directly in cmd/skilltrain with -loop-count.

Proof date: 2026-05-02

What changed

Native loop flag

-loop-count N repeats the full training run in the same Go process. The default is 1, preserving normal single-run behavior.

Equivalent Make target

make trainloop now calls go run ./cmd/skilltrain -iters 3 -judge -model openai-codex/gpt-5.5 -loop-count 21.

Supplied flags preserved

Every loop iteration uses the user-provided configuration instead of hardcoding model, judge, or iteration settings.

Run directory fan-out

When -run-dir is set and -loop-count > 1, runs write under loop-001, loop-002, etc.

Clear logs

The log prefix now reads skilltrain train loop: so nested output identifies the train-loop driver.

CLI exposes the loop flag

$ go run ./auto-improve-skills/cmd/skilltrain -h 2>&1 | rg -- '-loop-count|Usage'
Usage of /var/folders/2z/8sjtfr2n5p1313kwpcfrtdb40000gq/T/go-build2597458304/b001/exe/skilltrain:

make trainloop maps to native loop mode

$ cd auto-improve-skills && make -n trainloop
go run ./cmd/skilltrain \
		-model openai-codex/gpt-5.5 \
		-iters 3 \
		-judge \
		-loop-count 21

Added tests for defaults, repeated runner calls, run-dir suffixes, validation, and the train-loop log prefix.

Makefile

README.md

Documented -loop-count, repeated full-run semantics, and run-dir subdirectory behavior.

Result

The previous make trainloop semantics are implemented inside skilltrain.

  • -loop-count 21 performs 21 full runs and exits on the first error.
  • The model, judge, iteration count, and other flags are whatever the user supplied.
  • -run-dir safely fans out to per-loop subdirectories.
  • Logs visibly identify the skilltrain train loop.
