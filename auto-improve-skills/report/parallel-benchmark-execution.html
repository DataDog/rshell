Parallel benchmark execution is now on by default

Implemented parallel suites, repeats, and cases for skilltrain/skillbench, with bounded defaults requested by the user.

Proof date: 2026-05-01

What runs in parallel

Suite-level

Public and holdout baselines run concurrently. Candidate public benchmark and speculative holdout benchmark run concurrently when holdout is enabled.

Repeat-level

skilltrain runs benchmark repeats concurrently up to -parallel-repeats. Default: 3.

Case-level

skillbench runs selected cases concurrently up to -parallel-cases. Default: 2.

Safety setup

skilltrain prepares ./rshell and generated fixtures once before parallel runs, then disables per-run rebuild/regeneration.

Default flags prove bounded parallelism

$ go run ./cmd/skilltrain -h 2>&1 | awk '/parallel-cases|parallel-repeats|parallel-suites/{print; getline; print}'
  -parallel-cases int
    	maximum cases per skillbench run to execute concurrently (0 = all selected cases, 1 = serial) (default 2)
  -parallel-repeats int
    	maximum benchmark repeats to run concurrently (0 = all repeats, 1 = serial) (default 3)
  -parallel-suites
    	run independent public and holdout suites concurrently when possible (default true)

$ go run ./cmd/skillbench -h 2>&1 | awk '/parallel-cases/{print; getline; print}'
  -parallel-cases int
    	maximum benchmark cases to run concurrently (0 = all selected cases, 1 = serial) (default 2)
